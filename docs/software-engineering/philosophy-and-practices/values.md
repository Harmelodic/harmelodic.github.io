# Values

Values are the things we care about.

Values (in general) are usually treated as either very personal things that we hold close as individuals, or corporate
bullshit that organisations state to make their company & culture sound good, but they don't actually live by those
values, or the values themselves can be problematic.

When creating or considering different software principles or practices, it's important to consider what our values are.
Many values may be almost universal, but some values more subjective.

In the making of anything, we fundamentally have two areas in which values can be found:

1. The creation.
2. The means of how that creation is made.

In software engineering, this translates to:

1. Software - that achieves its functional & non-functional requirements.
2. Software Engineering - or at least _aspects_ software engineering.

Below are some examples of values that I think we (as a software engineering industry) have in these two areas.

## Values in Software

- We like usefulness.
- We like accessibility / it be used by anyone no matter their ability.
- We want security.
- We want reliability (this is the fundamental value behind all testing, resiliency and scaling efforts).
- We like efficiency.
- We like high performance / speed / responsiveness.
- We like intuitiveness.
- We like things to look good.
- We like simplicity.
- We like flexibility / configurability.
- We like portability.
- We want it to be cheap.
- We like longevity (maintained software).

## Values in Software Engineering

- We enjoy learning.
- We enjoy problem-solving.
- We enjoy being creative.
- We enjoy collaborating.
- We enjoy working solo.
- We like to know we're doing a good job.
- We like transparency (knowing what's going on)
- We like inclusivity (especially for things we are interested in being involved in)
- We like delegation and trust (especially for things we aren't interested in being involved in)
- We like evidence and reasoning to back decisions
- We like empathy and logic/rationality where evidence is lacking.
- We enjoy debate.
- We don't like arguing.
- We like to be challenged.
- We like things being easy / cheap.
- We like feeling zen / [flow](https://en.wikipedia.org/wiki/Flow_(psychology)).
- We don't like waste.
- We want to savour the experience.
- We like to know how things work.
- We don't care to know some things.
- We feel comfortable in structure.
- We like quick wins.
- We like long-term investments.

## Finding balance

Many values clash with one another, even the values across the two areas of Software and Software Engineering can be in
conflict - e.g. wanting to make software cheaper may involve in disregarding values we hold in Software Engineering.

> Good, fast, cheap - choose two.

This classic [project management triangle](https://en.wikipedia.org/wiki/Project_management_triangle) is a good example
of the quandaries we face when assessing our values and applying them, and balancing considerations is important and
choices need to be made.

However, it is important to not associate "balance" with "equality". Some values are more valued than others, both
objectively and depending on context, and treating some values more than they are actually valued is a recipe for shit
software and unpleasant software engineering.
